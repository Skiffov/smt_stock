# SMT Stock — чиста збірка

Навчальний монолітний вебзастосунок: **Python + Flask + Jinja2 + SQLite**. Інтерфейс для адміністратора, KIT-оператора й комірника. Призначено для локального тестування, **не для негайного впровадження на виробництві**.

## Запуск (Arch Linux, fish)

```fish
cd smt_stock
python -m venv .venv
source .venv/bin/activate.fish
python -m pip install -r requirements.txt
python app.py
```

Відкрити http://127.0.0.1:5000.

**Нова БД:** файл `smt_stock.sqlite3` створюється при першому запуску. Міграція старих баз даних не передбачена; файл до ZIP не включено. Початково є лише три тестові облікові записи та порожній каталог/склад:

| Роль | Код демо-картки |
|---|---|
| Адміністратор | `ADMIN001` |
| Комірник | `STORE001` |
| KIT-оператор | `OP001` |

## Дані компонентів

У каталозі `components` зберігаються **внутрішній артикул**, **тип**, **типорозмір**, **номінал** і **додаткова специфікація**. Назва автоматично складається з типу, типорозміру та номіналу. Інженерні вимоги тут фіксуються адміністратором; окремої ролі інженера немає.

**Виробник та MPN — поля фізичної упаковки** (`packages`), які заповнює комірник під час надходження. Один внутрішній компонент може мати кілька упаковок від різних виробників. ПЗ **не перевіряє** технологічну взаємозамінність MPN: підтвердження еквівалентності — відповідальність інженера/технолога за технічною документацією.

Кожна упаковка має тип (рулон, стрічка, трей, туба, розсип, інше), мітку, складський залишок у штуках, місце, стан та за потреби причину блокування. Рулони можна видавати цілими або частково (окреме підтвердження часткової видачі).

## Проєкти та виробничий цикл

- Поле `ipc_class` обмежене **Class 1 / Class 2 / Class 3 за IPC-A-610**. Це класи приймання виробів, а не показники технологічної складності.
- Адміністратор створює проєкт з BOM; компоненти можна додавати до каталогу безпосередньо з форми BOM.
- KIT-оператор приймає проєкт, після чого формується **одна автоматична заявка** за BOM. Додаткові заявки доступні.
- Комірник видає матеріали з конкретної упаковки; оператор підтверджує кожну видачу.
- Завершення формує відомість повернень, а комірник самостійно визначає фактичні залишки. Прийняті матеріали отримують окреме пакування `RETURN-*`, яке успадковує виробника, MPN і тип початкового пакування.
- Залишки за упаковками, блок-зона, історія, статистика по компонентах та «План / факт» за проєктами.
- Пошук, фільтри, сортування натисканням на заголовки таблиць. Темна та світла теми: `#121312`, `#ad0013`, `#a67d43`, кремова світла палітра.
- Рефакторинг: патерни **Repository** (`PackageRepository`) та **State** (стани проєкту).

## Тести

```fish
python test_logic.py
```

Тести використовують тимчасову БД і відмовляються стартувати, якщо поруч уже існує файл `smt_stock.sqlite3`, щоб не чіпати робочі дані. Для запуску тестів використовуйте чисту копію без БД.

У середовищі збірки перевірено бізнес-сценарії через підміну об’єктів Flask та синтаксис Jinja2; **браузерні й реальні HTTP-тести не виконувалися**. Перед реальним розгортанням потрібні надійніша автентифікація, HTTPS, резервне копіювання, конкурентне тестування та виробничий WSGI-сервер. Штрихкод картки є ідентифікатором, а не надійним паролем.
